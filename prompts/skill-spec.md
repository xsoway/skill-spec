# Skill Spec Prompt

创建或重构一个可独立安装、可评测、可演进的 Codex Skill 包。

## 输入

- Skill 的用户意图、触发语句、目标环境、输入来源、期望输出与授权边界。
- 可选：已有 Skill、真实失败样本、评测数据、Skill-up 配置、SkillOpt 训练候选与运行环境。

先声明已知事实、信息缺口、冲突、范围外和最小假设。缺少业务数据或外部工具时，完成静态包并明确未运行项。

## 你要做的事

1. 判断应新建 Skill、扩展既有 Skill，还是只修复 Prompt/评测；避免因名称相近创建重复包。
2. 创建完整目录：入口、主 Prompt、元数据、Eval、按需参考/示例/脚本，以及可执行结构校验。
3. 让入口保持短小，主 Prompt 写清输入、判断、最低覆盖、输出、质量和边界。
4. 为 Skill-up 提供静态可校验的 Eval，并区分 validate、dry-run、真实模型 run。
5. 仅在有版本化基线、批准数据、训练/验证/留出集隔离和人工晋升门禁时接入 SkillOpt。

## 执行规则

- `SKILL.md` 的 `name`、目录名、`agents/openai.yaml` 的 `metadata.key` 必须一致。
- 每个包必须有 `prompts/`、`agents/openai.yaml`、`evals/eval.yaml` 和三类 case；引用只链接包内相对文件。
- 真实密钥、个人数据、cookie、私钥与机器绝对路径不得进入任何 Skill 工件。
- Skill-up 运行只证明指定引擎/样本/版本的观测，不证明通用能力；未运行时必须标注。
- SkillOpt 只优化明确标出的可训练文本；不可训练合同、评测集、留出集和稳定版本不可被训练过程改写。

## 最低覆盖清单

- [ ] 触发准确：描述含“何时使用”和中英文常见触发词。
- [ ] 包完整：入口、Prompt、元数据、Eval、三类用例、验证脚本。
- [ ] 内容分层：入口只放路由和硬约束，细节按需加载。
- [ ] 安全边界：无秘密、无未授权外部动作、无伪造运行结论。
- [ ] 评测闭环：基线、失败原因、修复、回归；SkillOpt 还要有留出集晋升门禁。

## 输出

输出目录树、每个文件职责、验证命令/结果、未运行的外部评测、风险和回滚方式。默认 Markdown。

## 质量要求

- 不堆砌与当前工程无关的仓库分类、安装器、发布流程或框架专属描述。
- 静态包校验、Skill-up validate、模型评测、SkillOpt 训练和生产部署必须分别报告。
- 优化前备份稳定版本；候选退化、留出集不足或人工门禁未过时不晋升。
